# 📋 SOFTWARE ENGINEERING PROJECT

## **PHASE 1: IDENTIFYING AND DEFINING**

### Defining Problem Requirements

**Outcomes:** SE-12-01, SE-12-06

Define and analyse the requirements of a problem to ensure viability and purpose:

- **Demonstrating needs or opportunities:** Clearly identify the real-world problem the software solves
- **Assessing scheduling and financial feasibility:** Determine if the project can be completed within allocated timeframe and budget
- **Generating requirements:** Define functionality (what the system must do) and performance (how well/fast)
- **Defining data structures and data types:** Specify how information will be securely collected and stored
- **Defining boundaries:** Establish scope to prevent scope creep during development

### Tools for Development

**Outcomes:** SE-12-06

Explore tools used to develop ideas and generate solutions:

- **Brainstorming, mind-mapping, and storyboards:** Visualise user interfaces and user journeys
- **Data dictionaries:** Define data items, types, sizes, valid ranges, and validation rules
- **Algorithm design:** Create flowcharts and pseudocode for core logic
- **Code generation:** Implement algorithms using chosen programming language
- **Testing and debugging:** Validate system behaviour against requirements
- **Installation:** Deploy the working system to the operational environment
- **Maintenance:** Plan for ongoing updates and support

### Implementation Methods

**Outcomes:** SE-12-01

Investigate types of software implementation methods:

- **Direct:** Complete replacement of old system with new system at a single point in time
- **Phased:** Implement the new system in stages, one module or department at a time
- **Parallel:** Run old and new systems side-by-side until new system is proven stable
- **Pilot:** Test the new system with a small user group before full rollout

## **PHASE 2: RESEARCH AND PLANNING**

### Development Approaches

**Outcomes:** SE-12-02

Research software development approaches:

**Waterfall:**
- Logical progression through distinct phases (requirements → design → implementation → testing → deployment)
- Advantages: Clear structure, easy to plan and estimate, good for well-defined requirements
- Disadvantages: Inflexible to changes, issues discovered late are expensive to fix
- Best for: Large-scale projects with stable requirements

**Agile:**
- Iterative development with frequent releases and continuous feedback
- Advantages: Flexibility to change, early delivery of working software, reduces risk
- Disadvantages: Requires active client involvement, harder to estimate timeline and cost
- Best for: Projects with evolving or unclear requirements, need for rapid delivery

**WAgile (Waterfall-Agile Hybrid):**
- Combines structured planning phases (Waterfall) with iterative implementation (Agile)
- Advantages: Structured planning with flexible implementation; manages large teams effectively
- Disadvantages: Complex to manage; requires discipline in both planning and execution
- Best for: Large government or enterprise projects needing both structure and flexibility

### Project Management and Communication

**Outcomes:** SE-12-02

Apply project management to plan and conduct development:

- **Scheduling and tracking:** Use project management tools (Gantt charts, task lists) to plan milestones and track progress
- **Collaboration tools:** Use version control (Git), communication platforms, and shared documentation
- **Involving and empowering the client:** Regular consultations to gather requirements and feedback
- **Enabling feedback:** Demonstrate progress, request input, and respond to concerns systematically
- **Negotiating:** Balance client needs with technical constraints and resource limitations

### Quality Assurance and Back-End Engineering

**Outcomes:** SE-12-03, SE-12-08

Investigate how software engineering solutions are quality assured:

- **Defining quality criteria:** Establish measurable standards by which the system will be judged
- **Continual checking:** Apply systematic testing throughout development, not just at the end
- **Compliance and legislative requirements:** Ensure adherence to relevant standards and regulations

Explain the contribution of back-end engineering to software development:

- **Technology used:** Selection of appropriate platforms, frameworks, and databases for reliability and performance
- **Error handling:** Graceful handling of exceptions and edge cases to prevent system crashes
- **Interfacing with front end:** Well-designed APIs and data contracts that allow front-end and back-end to develop independently
- **Security engineering:** Implementing authentication, authorization, encryption, and protection against common vulnerabilities

## **PHASE 3: PRODUCING AND IMPLEMENTING**

### Design and Implementation

**Outcomes:** SE-12-02, SE-12-07

- **Design:** Create architecture and detailed specifications before coding
- **Implementation:** Write, test, and integrate code following the design specifications
- **Presentation:** Prepare and deliver a presentation of the completed solution using presentation software

### Documentation and Version Control

**Outcomes:** SE-12-02, SE-12-07, SE-12-09

- **Develop and document algorithms:** Include pseudocode and flowcharts for key logic
- **Programmed data backup:** Implement automatic backup procedures to prevent data loss
- **Version control:** Use Git or similar tools to track changes, manage collaboration, and enable rollback if needed

### Resource Allocation and Problem-Solving

**Outcomes:** SE-12-02, SE-12-07

- **Allocate resources:** Plan and manage time, people, and materials effectively
- **Respond to difficulties:** Apply strategies including online research, peer collaboration, and outsourcing when needed
- **Propose innovative enhancements:** Develop prototypes and UI designs for additional features beyond core requirements

---

## **PHASE 4: TESTING AND EVALUATING**

### Testing Methodology

**Outcomes:** SE-12-08, SE-12-09

- **Apply methodologies to test and evaluate code:** Develop test plans with specific test cases
- **Path testing:** Test different execution paths through the code to ensure all logic branches work correctly
- **Boundary testing:** Test values at the edges of valid ranges (e.g., minimum, maximum, and just beyond) to catch off-by-one errors
- **Develop test data:** Create representative test cases based on real-world usage patterns

### Code Optimisation and Feedback

**Outcomes:** SE-12-08

- **Language-dependent code optimisation:** Apply techniques specific to the programming language used to improve efficiency, readability, or performance
- **Analyse and respond to feedback:** Systematically incorporate user and stakeholder feedback into the final solution

### Effectiveness Evaluation

**Outcomes:** SE-12-09

**Evaluate the effectiveness of a software engineering solution:**

- **Develop a report to synthesise feedback:** Collect and summarise feedback from users, stakeholders, and testing
- **Develop a test plan:** Document all testing activities and results
- **Compare actual output with expected output:** Systematically verify that each requirement is met by demonstrating actual system behaviour against the original specifications

## 📖 Why the Software Engineering Project Matters

The Software Engineering Project enables students to:
- Apply knowledge from all Year 11 and Year 12 focus areas to solve a real-world problem
- Develop and practise professional project-management and software development skills
- Experience collaboration, communication, and stakeholder management
- Conduct systematic evaluation to ensure solutions meet requirements
- Develop deeper expertise in an area of personal interest through sustained engagement

This major project is the capstone of the Software Engineering course, demonstrating mastery of the complete software development lifecycle.

Why this matters now

Every app on your phone started as an algorithm someone sketched in pseudocode. Today, AI coding assistants can generate hundreds of lines in seconds, but they still get logic wrong, pick the wrong data structure or miss an edge case, and it takes an engineer who understands sequence, selection, iteration, number systems and testing to spot the bug before it ships. The 2024 CrowdStrike outage, which grounded flights and froze hospital systems worldwide, came down to one faulty input that was never properly tested.

In this topic you will learn the core toolkit the syllabus calls programming fundamentals: the software development steps, designing and analysing algorithms, representing data, and testing and debugging your own code.

Ask yourself as you go If an AI wrote this code for me, how would I prove it is correct?

The development and integration steps turn that design into Python. Each subroutine is written and tried on its own, then main joins them.

Python: development and integration
DISCOUNT_ITEMS = 10          # orders this size or larger get a discount
DISCOUNT_PERCENT = 10

def read_whole_number(prompt):
    """Keep asking until the user types a whole number of 0 or more."""
    while True:
        text = input(prompt)
        if text.isdigit():
            return int(text)
        print("Please enter a whole number of 0 or more.")

def get_order():
    items = 0
    total = 0                    # cents
    price = read_whole_number("Price in cents (0 to finish): ")
    while price != 0:
        quantity = read_whole_number("Quantity: ")
        items = items + quantity
        total = total + price * quantity
        price = read_whole_number("Price in cents (0 to finish): ")
    return items, total

def apply_discount(total, items):
    if items >= DISCOUNT_ITEMS:
        return total - total * DISCOUNT_PERCENT // 100
    return total

def format_dollars(cents):
    return f"${cents // 100}.{cents % 100:02d}"

def main():
    items, total = get_order()
    total = apply_discount(total, items)
    print("Total:", format_dollars(total))

main()

Requirements versus specifications Requirements say what the client needs in the client’s words (“staff must be able to reprint a receipt”). Specifications say how well and on what the software must do it, in technical terms (“responds in under a second on a 4 GB laptop”). Requirements come first and drive the specifications.

Why the steps form a cycle

The steps are drawn in order, but real projects loop. A test failure sends the team back to development, a design flaw found during integration sends them back to design, and maintenance requests become the requirements for the next version. The flow is a cycle, not a one-way street. The SDLC Guide compares this ordered view with Waterfall and Agile, which are covered later on this page.

Exam tip: “Explore” An explore question is open, so cover more than a list. Name the steps that matter to the scenario, say what each produces, and show how they connect: “the specification gives design its constraints; testing sends faults back to development.” Anchor the answer in one concrete project, as above. Common mistakes are treating requirements and specifications as the same step, and forgetting that maintenance continues after installation.

Resolving a merge conflict

A merge conflict happens when two branches change the same lines. Git cannot decide which version is right, so it marks both in the file and waits for a person to choose.

What Git writes into the file
def apply_discount(total, items):
<<<<<<< HEAD
    if items >= 10:
=======
    if items >= 8:
>>>>>>> add-teacher-discount
        return total - total * 10 // 100

Everything between <<<<<<< HEAD and ======= is the version on the current branch; everything down to >>>>>>> is the incoming version. The developer keeps one version (or combines them), deletes the marker lines, tests, then commits. Talking to the teammate first is often faster than guessing which threshold is right.

Key Features of Standard Algorithms

🎯 (SE-11-02)

📌 Apply computational thinking and algorithmic design by defining the key features of standard algorithms, including sequence, selection, iteration and identifying data that should be stored

Every algorithm uses fundamental building blocks to solve problems. Understanding these features allows programmers to design robust, efficient solutions:

1. Sequence

Sequence means instructions are executed in order, one after another. Each step completes before the next begins — there is no branching or repetition.Reading a file, processing each line, then saving results.

pseudocode 
BEGIN
    OUTPUT "Enter the length: "
    INPUT length
    OUTPUT "Enter the width: "
    INPUT width
    area ← length * width
    OUTPUT "The area is: ", area
END

2. Selection

Selection means choosing different execution paths based on conditions using IF … ELSE, nested IF or a multi-way CASEWHERE structure. The program evaluates a condition and branches accordingly.Validating user input — if age < 18, display "Too young"; otherwise, proceed.

pseudocode 
BEGIN
    OUTPUT "Enter your age: "
    INPUT age
    IF age >= 18 THEN
        OUTPUT "Welcome!"
        ShowFullMenu ()
    ELSE
        OUTPUT "Too young - access denied."
    ENDIF
END

Two more selection forms appear in NESA’s Course Specifications. Multi-way selection chooses one of several cases by evaluating a single expression, and only one branch runs. It is written CASEWHERE … OTHERWISE … END CASE.

Pseudocode
CASEWHERE menuChoice evaluates to
    1: OUTPUT "New game"
    2: OUTPUT "Load game"
    3: OUTPUT "High scores"
    OTHERWISE: OUTPUT "Invalid choice"
END CASE

Nested IF tests several conditions in turn when only one process should run. Each further test is a complete IF indented inside the ELSE of the one before it, and every IF has its own ENDIF.

Pseudocode
IF mark >= 85 THEN
    OUTPUT "High"
ELSE
    IF mark >= 65 THEN
        OUTPUT "Medium"
    ELSE
        IF mark >= 50 THEN
            OUTPUT "Pass"
        ELSE
            OUTPUT "Fail"
        ENDIF
    ENDIF
ENDIF
Count the ENDIFs Three IF lines need three ENDIF lines, closed from the inside out. If the counts do not match, the structure is wrong. Python’s elif expresses the same nested decision in shorter form.

3. Iteration

Iteration means repeating a set of instructions while a condition is true, using FOR or WHILE loops. The loop body executes multiple times until the exit condition is met.Summing all numbers in a list by looping through each element.

pseudocode 
BEGIN
    numbers ← [10, 25, 3, 47, 8]
    total ← 0
    FOR i = 0 TO LENGTH(numbers) - 1
        total ← total + numbers[i]
    NEXT i
    OUTPUT "The sum is: " + total
END

NESA describes three loops. WHILE is a pre-test loop, so its body may never run. REPEAT … UNTIL is a post-test loop, so its body always runs at least once, which suits input validation. FOR … NEXT is a counted loop; STEP sets the increment and can be negative.

4. Storing Data

Storing Data means using variables and data structures to hold values needed across multiple steps of an algorithm. Without stored state, programs cannot track progress or accumulate results.Keeping track of a running total as you iterate through numbers.

pseudocode 
BEGIN
    runningTotal ← 0
    count ← 0
    OUTPUT "Enter numbers (-1 to finish): "
    INPUT number
    WHILE number != -1
        runningTotal ← runningTotal + number
        count ← count + 1
        INPUT number
    ENDWHILE
    IF count > 0 THEN
        average ← runningTotal / count
        OUTPUT "Average: " + average
    ELSE
        OUTPUT "No data entered."
    ENDIF
END

Identifying the data that should be stored

Before writing steps, decide what the algorithm must remember. Three questions find every stored item: what comes in (inputs), what must be carried from one step to the next (state such as totals, counters and “best so far”), and what goes out (outputs). Anything that does not need to survive to the next step can be a temporary value.

Worked example: the highest mark and the number of passes

Problem: marks are typed in one at a time until -1 is entered. Report the highest mark and how many students scored 50 or more.

Computational thinking

Computational thinking is the habit behind every design above. It has four parts, and you use all four whenever you plan an algorithm.

DecompositionBreaking a big problem into smaller parts you can solve separately, such as get input, process, report.
Pattern recognitionSpotting that a new problem resembles one you have solved, such as “find the largest” and “find the smallest”.
AbstractionKeeping the details that matter and ignoring the rest, such as treating a student as an ID and a mark.
Algorithm designWriting the exact steps, using sequence, selection and iteration, so anyone (or a computer) can follow them.
Exam tip: “Apply” An apply question gives you a situation and expects the ideas used on it, not a definition. If asked to design an algorithm for a scenario, name what is stored, use the correct NESA keywords with matching pairs (IF/ENDIF, WHILE/ENDWHILE, FOR/NEXT) and indent each structure. Marks are lost for a loop that never changes its condition, an accumulator that is not initialised, and mixing up WHILE and REPEAT … UNTIL.

By combining sequence, selection, iteration and effective data storage, algorithms become clear, testable and maintainable.

Divide and Conquer, and Backtracking

🎯 (SE-11-02)

📌 Apply divide and conquer and backtracking as algorithmic design strategies

Divide and Conquer

This strategy involves breaking a complex problem into smaller, identical sub-problems until they are simple enough to solve directly. The solutions to these sub-problems are then combined to form the final result.In a Merge Sort, a large list is repeatedly split in half until single elements remain, which are then merged back together in the correct order. This approach is highly efficient for sorting and searching large datasets.

The three steps

  1. Divide the problem into smaller sub-problems of the same kind.
  2. Conquer each sub-problem, by solving it directly when it is small enough (the base case) or by applying the same method again.
  3. Combine the sub-solutions into the answer to the original problem. Binary search needs no combining because it discards the half that cannot contain the target.

Worked example: binary search

Binary search finds a target in a sorted list by checking the middle item and discarding the half that cannot contain it. NESA-style pseudocode for the algorithm:

Pseudocode
BEGIN BinarySearch (list, target)
    low ← 0
    high ← LENGTH(list) - 1
    WHILE low <= high
        mid ← whole number part of (low + high) / 2
        IF list[mid] = target THEN
            RETURN mid
        ELSE
            IF list[mid] < target THEN
                low ← mid + 1
            ELSE
                high ← mid - 1
            ENDIF
        ENDIF
    ENDWHILE
    RETURN -1
END BinarySearch (list, target)

Trace it with the sorted list [12, 19, 25, 31, 44, 57, 63, 78, 90] (indexes 0 to 8) and the target 57:

10844444 < 57Discard the left half: low ← 5
25866363 > 57Discard the right half: high ← 5
35555757 = 57Found: RETURN 5

Three comparisons found the target. Linear search would have needed six. For a target that is absent, such as 50, the same three passes end with low greater than high and the algorithm returns -1. Step through binary search yourself in the interactive trace in the next section.

python
def binary_search(items, target):
    low = 0
    high = len(items) - 1
    while low <= high:
        mid = (low + high) // 2
        if items[mid] == target:
            return mid
        elif items[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

Worked example: merge sort

Merge sort divides until every list has one item (a list of one item is already sorted, so this is the base case), then combines by merging two sorted lists into one. Here the list [38, 27, 43, 3, 9, 82, 10] is divided and then combined:

PhaseLists at this stage
Start[38, 27, 43, 3, 9, 82, 10]
Divide[38, 27, 43] and [3, 9, 82, 10]
Divide again[38] [27, 43] and [3, 9] [82, 10]
Base case: single items[38] [27] [43] and [3] [9] [82] [10]
Merge pairs[27, 43] and [3, 9] and [10, 82]
Merge again[27, 38, 43] and [3, 9, 10, 82]
Final merge[3, 9, 10, 27, 38, 43, 82]
python
def merge_sort(items):
    if len(items) <= 1:                 # base case
        return items
    middle = len(items) // 2
    left = merge_sort(items[:middle])   # divide and conquer each half
    right = merge_sort(items[middle:])
    merged = []
    i = j = 0
    while i < len(left) and j < len(right):   # combine: merge two sorted lists
        if left[i] <= right[j]:
            merged.append(left[i])
            i = i + 1
        else:
            merged.append(right[j])
            j = j + 1
    return merged + left[i:] + right[j:]

print(merge_sort([38, 27, 43, 3, 9, 82, 10]))
Output
[3, 9, 10, 27, 38, 43, 82]

Why it is efficient

Each pass halves the range, so doubling the list adds only one more comparison. That is why binary search is described as O(log n) and linear search as O(n). The price is the requirement that the data is already sorted. Merge sort takes roughly n log n steps, far fewer than the n² of bubble sort on a large list.

Backtracking

Backtracking is an incremental approach to problem-solving that builds a solution one step at a time. If the algorithm reaches a state where the current path cannot possibly lead to a valid solution (violating a constraint), it "backtracks" to the previous step and tries a different option.A Sudoku Solver attempts a number in a cell; if it later finds a conflict, it returns to that cell and tries the next available number. This strategy is essential for pathfinding and optimisation problems.

Python — Algorithmic Strategies
# Divide and Conquer: Recursive Binary Search
def binary_search(arr, target, low, high):
    if low > high: return -1
    mid = (low + high) // 2
    if arr[mid] == target: return mid
    elif arr[mid] > target:
        return binary_search(arr, target, low, mid - 1)
    else:
        return binary_search(arr, target, mid + 1, high)

# Backtracking: Maze Pathfinding (tries 4 directions)
visited = set()
def find_path(x, y, maze):
    if is_exit(x, y): return True
    if is_wall(x, y) or (x, y) in visited: return False

    visited.add((x, y)) # Mark as visited
    # Try all 4 directions: right, down, left, up
    for dx, dy in [(1, 0), (0, 1), (-1, 0), (0, -1)]:
        if find_path(x + dx, y + dy, maze):
            return True

    return False # Backtrack to previous cell

Worked example: a maze, step by step

The maze below has a wrong turn built in. The search tries directions in the order right, down, left, up. Watch the call stack on the right: each recursive call adds a line, and a dead end removes lines as the function returns False and control backs up to an earlier choice.

The complete function below matches the animation. The variable path collects the squares on the winning route as each call returns True, so it is built from the exit back to the start.

python
MAZE = ["...#.",
        "##.#.",
        ".....",
        ".####",
        "....."]
ROWS, COLS = len(MAZE), len(MAZE[0])
visited = set()
path = []

def find_path(x, y):
    """Return True if the exit (bottom-right) can be reached from (x, y)."""
    if (x, y) == (COLS - 1, ROWS - 1):
        path.append((x, y))
        return True                                   # base case: exit found
    if not (0 <= x < COLS and 0 <= y < ROWS):
        return False                                  # off the grid
    if MAZE[y][x] == "#" or (x, y) in visited:
        return False                                  # wall, or already tried
    visited.add((x, y))
    for dx, dy in [(1, 0), (0, 1), (-1, 0), (0, -1)]: # right, down, left, up
        if find_path(x + dx, y + dy):
            path.append((x, y))
            return True
    return False                                      # dead end: backtrack

print(find_path(0, 0))
print(path[::-1])

def is_safe(columns, row, col):
    """columns[r] is the column of the queen already placed in row r."""
    for r, c in enumerate(columns):
        if c == col or abs(c - col) == row - r:   # same column or same diagonal
            return False
    return True

def place_queens(columns, size):
    row = len(columns)
    if row == size:
        return True                               # every row has a queen
    for col in range(size):
        if is_safe(columns, row, col):
            columns.append(col)                   # try this square
            if place_queens(columns, size):
                return True
            columns.pop()                         # undo it: backtrack
    return False

Recursive Functions

A recursive function is one that calls itself. Every recursive function must have:

  • Base case: The condition that stops the recursion (no more recursive calls).
  • Recursive case: Where the function calls itself with a simpler input, moving toward the base case.
Always define a base case! Without a base case, the function calls itself indefinitely, causing a RecursionError: maximum recursion depth exceeded (stack overflow).
Python — Factorial: iterative vs recursive
# Iterative approach
def factorial_iterative(n):
    result = 1
    for i in range(1, n + 1):
        result *= i
    return result

# Recursive approach
def factorial_recursive(n):
    if n == 0 or n == 1:   # Base case
        return 1
    return n * factorial_recursive(n - 1)   # Recursive case

print(factorial_iterative(5))   # 120
print(factorial_recursive(5))   # 120

# Call stack for factorial_recursive(4):
# factorial(4) → 4 × factorial(3)
#   factorial(3) → 3 × factorial(2)
#     factorial(2) → 2 × factorial(1)
#       factorial(1) → returns 1   ← base case reached
#     factorial(2) → returns 2
#   factorial(3) → returns 6
# factorial(4) → returns 24
Python — Fibonacci (recursive)
def fibonacci(n):
    if n <= 1:           # Base cases: fib(0)=0, fib(1)=1
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)

for i in range(8):
    print(fibonacci(i), end=" ")
# Output: 0 1 1 2 3 5 8 13
When to use recursion vs iteration Use recursion when the problem is naturally recursive (tree traversal, factorial, divide-and-conquer). Use iteration when you need performance — recursive calls create function stack frames that use more memory. Python's default recursion limit is 1000 calls.

Pseudocode

Pseudocode is an informal, human-readable notation for writing algorithms — a bridge between natural language and programming code. It uses common programming keywords (IF, WHILE, FOR) mixed with English-like descriptions, making logic crystal clear without being tied to a specific programming language's syntax. This allows designers and developers to communicate algorithm logic to non-programmers, and to verify correctness before investing time in actual coding.Example:

Pseudocode: linear search

        IF list[index] = target THEN
            RETURN index
        ENDIF

END SearchList (list, target)

Flowcharts

Flowcharts use visual symbols to represent algorithm steps and decision points. Rectangles represent processes, diamonds represent decisions, and arrows show flow direction. This visual representation makes complex logic easy to follow, helps identify loops and branches, and allows stakeholders to validate correctness before implementation.Example: A flowchart for validating user age would show a diamond (decision point) — "Is age ≥ 18?" — with two paths: YES leads to "Show full menu" and NO leads to "Show restricted menu."

Modelling Tools for Top-Down and Bottom-Up Design

🎯 (SE-11-02)

📌 Use modelling tools including structure charts, abstraction and refinement diagrams to support top-down and bottom-up design

Structure Charts

Structure charts are a top-down tool used to show the hierarchy of subroutines in a system. They focus on modularity, showing which module calls another and what data (parameters) or control signals (flags) are passed between them.A structure chart for an ATM would show the 'Main' module calling 'Verify PIN' and passing back a 'Valid/Invalid' flag. This allows engineers to see high-level dependencies without getting bogged down in code logic.

Abstraction and Refinement

Abstraction involves hiding implementation details to focus on high-level goals (the 'What'). Stepwise Refinement is the process of breaking those high-level goals into smaller, more specific details (the 'How').An abstract instruction like 'Initialise System' is refined into 'Set counter to 0', 'Clear display', and 'Open file stream'. Together, they allow for manageable development of complex systems.

Top-down and bottom-up design

Top-down design starts with the whole problem and breaks it into smaller and smaller subroutines until each is simple enough to code. Bottom-up design starts with small, tested building blocks (or existing library functions) and joins them into larger parts. Most real projects use both: plan from the top, but build on reliable pieces at the bottom.

Programming Paradigms

🎯 (SE-11-02)

Object-Oriented Programming (OOP)

Data and functions are bundled together in "objects" that model real-world entities. Emphasises reusability, modularity, and maintainability. Classes define blueprints; instances are created from them.A Car class has properties (colour, speed) and methods (accelerate(), brake()); multiple car objects can be created from this template.

Imperative Programming

Programs are sequences of explicit commands (statements) that change program state step-by-step. Python, Java, and C are imperative languages. Focus on "how" to solve the problem (procedures and control flow)."Set count to 0; LOOP: add next number to count; increment loop counter; IF loop counter < 10, GO TO LOOP."

Logic Programming

Programs state facts and rules; the interpreter derives new facts through logical inference. Less common than imperative, but heavily used in artificial intelligence, constraint logic, and database query planning. Focus on "what" is true, not "how" to compute it.

Converting between bases

  • Binary → decimal: add the place values that hold a 1. For 1011: 8 + 0 + 2 + 1 = 11.
  • Decimal → binary: divide by 2 repeatedly and read the remainders from bottom to top.
  • Binary ↔ hexadecimal: split the binary into groups of four bits. 1010 1111 → A F → AF.
Why hexadecimal? One hex digit stands for exactly four bits, so a byte is always two hex digits. That makes long binary values, such as memory addresses and colour codes, much shorter and easier to read.

Place value in three bases

Every base works the same way: each digit is worth the digit times a place value, and each place is the base times bigger than the one on its right. Decimal places are powers of 10, binary places are powers of 2 and hexadecimal places are powers of 16.

Two's Complement

🎯 (SE-11-03)

📌 Represent integers using two’s complement

Two's Complement is the standard method for representing signed (negative) integers in binary. To represent a negative number, the bits of the positive equivalent are inverted (0 to 1 and vice-versa) and 1 is added to the result. This system is preferred as it allows for simple addition/subtraction circuits and eliminates the 'double zero' (+0 and -0) problem used in older systems.

Worked Example — Representing -5 in 8-bit Two's Complement:
  1. Start with the positive number: 5 = 00000101
  2. Invert all bits (One's Complement): 11111010 (each 0 becomes 1, each 1 becomes 0)
  3. Add 1 to the result: 11111010 + 1 = 11111011
  4. Result: -5 in 8-bit Two's Complement = 11111011

Verification: If we add 5 and -5 in binary: 00000101 + 11111011 = 100000000 (the overflow bit carries out, leaving 00000000 = 0 ✓)

Why two’s complement?

A computer needs a way to store negative whole numbers using only 0s and 1s. The simplest idea is to use the left-hand bit as a sign, but that gives two zeros (+0 and −0) and makes subtraction awkward. In two’s complement there is one zero, and the same adding circuit handles positive and negative numbers.

Range of an n-bit number

The left-hand bit is the sign bit: 0 for zero and positive numbers, 1 for negative numbers. With n bits the range is −2n−1 to 2n−1 − 1. There is one more negative value than positive.

Reading a negative pattern

To find the value of 11110110: the sign bit is 1, so it is negative. Invert the bits (00001001), add 1 (00001010 = 10) and put a minus sign in front: −10. You can check with signed place values: the sign bit is worth −128, so −128 + 64 + 32 + 16 + 4 + 2 = −10.

Subtraction becomes addition

To calculate 7 − 5, add 7 and −5: 00000111 + 11111011 = 1 00000010. The carry out of the eighth bit is discarded, leaving 00000010, which is 2.

Overflow

If a result does not fit in the available bits, it wraps round. In 8 bits, 01111111 (127) plus 1 is 10000000, which is −128. This is overflow, and it is why the Year 2038 problem in the section introduction matters: a 32-bit signed count of seconds runs out of positive values in January 2038.

print(f"{-20 & 0xFF:08b}")          # 11101100
print(int("11110110", 2) - 256)     # -10

In Python, & 0xFF keeps only the lowest eight bits, which is what an 8-bit store would keep. Subtracting 256 (28) from a pattern whose sign bit is 1 gives its signed value.

single precision floating point

Single precision uses 32 bits (4 bytes) for a real number: 1 sign bit, 8 bits for the exponent (the scale) and 23 bits for the fraction (the digits). That gives about 7 significant decimal digits. Values beyond that precision are rounded, as the next example shows.

python
import struct

def as_single(value):
    """Store value as a 32-bit float and read it back."""
    return struct.unpack("f", struct.pack("f", value))[0]

print(as_single(0.1))         # 0.10000000149011612
print(as_single(16777217))    # 16777216.0
Output
0.10000000149011612
16777216.0

The first line shows that 0.1 cannot be stored exactly. The second shows that after 16 777 216 (224) single precision can no longer represent every whole number, so 16 777 217 is stored as 16 777 216. Double precision (64 bits) is the default real type in Python and gives about 15 to 16 digits.

Parameter Passing

Pass by value: A copy of the variable is sent. The original variable in the caller is unchanged, even if the function modifies the parameter.

Python — Pass by value (immutable)
def double(n):
    n = n * 2     # modifies the local copy only
    return n

score = 50
result = double(score)
print(score)    # still 50 — original unchanged
print(result)   # 100

Pass by reference (mutable objects): Python passes a reference to the object. Mutable types (lists, dicts) can be modified inside the function — the caller sees the change.

Python — Pass by reference (mutable)
def add_score(scores, new_score):
    scores.append(new_score)   # modifies the original list

results = [80, 75, 90]
add_score(results, 95)
print(results)   # [80, 75, 90, 95] — list WAS modified
Python Mutability Rule Python passes a reference to the object. Immutable types (int, float, str, tuple) cannot be changed in place, so a function cannot change the caller's variable and the result behaves like pass-by-value. Mutable types (list, dict, set) can be changed in place, so changes inside a function are seen by the caller. Reassigning the parameter (scores = []) only re-points the local name and never changes the caller's list.

Variable Scope

Scope determines which parts of your program can access a variable. Python uses the LEGB rule to look up names:

LEGB Lookup Order
─────────────────────────────────────────────
L  Local      — variables defined inside the current function
E  Enclosing  — variables in any enclosing (outer) function
G  Global     — variables defined at module level
B  Built-in   — Python's built-in names (print, len, range…)
─────────────────────────────────────────────
Python searches L → E → G → B until the name is found.
Python — Scope examples
x = 10           # Global scope

def show():
    x = 99       # Local scope — shadows the global x
    print(x)     # 99

show()
print(x)         # 10 — global unchanged

# Using global keyword (avoid when possible)
counter = 0
def increment():
    global counter
    counter += 1

increment()
print(counter)   # 1
Best Practice Prefer returning values over using global variables. Global state makes programs harder to debug and test. If multiple functions need the same data, pass it as a parameter.

A binary search tree keeps smaller values to the left and larger to the right, so an in-order walk visits values in sorted order.

python
class Node:
    def __init__(self, value):
        self.value = value
        self.left = None
        self.right = None

def insert(node, value):
    if node is None:
        return Node(value)                     # base case: an empty spot
    if value < node.value:
        node.left = insert(node.left, value)
    else:
        node.right = insert(node.right, value)
    return node

def in_order(node):
    if node is not None:
        in_order(node.left)
        print(node.value, end=" ")
        in_order(node.right)

root = None

The undo example above pushes and pops. Stacks also check that brackets match: push each opening bracket and pop when a closing one appears.

def balanced(text):
    stack = []
    pairs = {")": "(", "]": "["}
    for ch in text:
        if ch in "([":
            stack.append(ch)                              # push
        elif ch in ")]":
            if not stack or stack.pop() != pairs[ch]:     # pop and compare
                return False
    return not stack                                      # nothing left open

Hash tables

Python’s dict is a hash table. Building a small one shows what happens inside: a hash function picks a slot, and each slot holds a short list so that colliding keys can share it.

python
class HashTable:
    def __init__(self, size=7):
        self.slots = [[] for _ in range(size)]

    def _index(self, key):
        return sum(ord(c) for c in key) % len(self.slots)

    def put(self, key, value):
        bucket = self.slots[self._index(key)]
        for pair in bucket:
            if pair[0] == key:             # key already stored: replace
                pair[1] = value
                return
        bucket.append([key, value])

    def get(self, key):
        for k, v in self.slots[self._index(key)]:
            if k == key:
                return v
        return None

table = HashTable()
table.put("Ava", 72)
table.put("Dev", 55)                        # collides with Ava in slot 0
table.put("Ben", 85)
print(table.get("Dev"), table.get("Ava"), table.get("Zed"))
print(table.slots[0])
Output
55 72 None
[['Ava', 72], ['Dev', 55]]

How each model runs

Waterfall runs the development steps as a sequence of phases, each finished and signed off before the next begins: requirements, design, development, testing, installation, maintenance. It relies on getting the requirements right at the start, because going back is costly. Agile repeats the steps in short cycles. The Agile Manifesto values working software, customer collaboration and responding to change over comprehensive documentation, contracts and following a plan, though it still values the items on the right.

Evaluating performance without a stopwatch

Counting the steps an algorithm takes is a fair way to compare designs, because it does not depend on the computer. Count comparisons for linear and binary search on a sorted list of 1000 numbers, looking for the last one:

python
def linear_comparisons(items, target):
    count = 0
    for item in items:
        count += 1
        if item == target:
            break
    return count

def binary_comparisons(items, target):
    low, high, count = 0, len(items) - 1, 0
    while low <= high:
        mid = (low + high) // 2
        count += 1
        if items[mid] == target:
            break
        elif items[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return count

data = list(range(1, 1001))
print(linear_comparisons(data, 1000), binary_comparisons(data, 1000))

Debugging Tools

🎯 (SE-11-06, SE-11-07)

📌 Use debugging tools

  • breakpoints
  • single line stepping
  • watches
  • interfaces between functions
  • debugging output statements
  • debugging software available in an integrated development environment (IDE)

Breakpoints

A breakpoint is an instruction set within an IDE (such as Visual Studio Code or PyCharm) that pauses program execution at a specific line, allowing the engineer to inspect the current state of all variables and memory at that exact moment. For example, when debugging a loop that is supposed to accumulate a total but is producing an incorrect result, placing a breakpoint at the beginning of each iteration allows the engineer to examine the running total before and after each calculation — pinpointing precisely where the logic diverges from the expected behaviour without having to add print statements throughout the code.

Watches

A watch is a debugging feature that continuously monitors the value of a specific variable as the program executes, updating in real time with each statement. This is particularly useful when a variable is modified across multiple functions or modules. For example, setting a watch on a total_price variable allows an engineer to observe exactly at which line — and within which function — an incorrect GST calculation is being applied, rather than manually tracing through the entire codebase to find the source of the discrepancy.

Single Line Stepping

Single line stepping (also known as "step-through" debugging) executes the program one statement at a time, pausing after each line. This allows engineers to trace the exact path of execution through complex control structures — such as nested conditionals or recursive functions — verifying that each branch evaluates as intended. For example, stepping through an IF/ELIF/ELSE chain confirms which condition is evaluating to True for a particular input, revealing logical errors in the control flow that would be completely invisible during normal, uninterrupted execution.

Python — Evaluative Testing and Debugging
def process_input(value):

        if 1 <= n <= 100: return "Valid" # Boundary check
        else: return "Out of Range"

# Example testing

Choosing Test Data

🎯 (SE-11-06, SE-11-07)

📌 Determine sets of suitable test data

  • boundary values
  • path coverage
  • faulty and abnormal data

Good test data is chosen on purpose, not typed at random. A small, well-chosen set can find most errors. Imagine a program that accepts a mark from 1 to 100.

Test Data Selection

Test Data Set Analysis / Purpose Example (Range 1-100)
Boundary Tests the exact limits of valid input ranges. 1 and 100
Abnormal Tests how the program handles invalid types or out-of-range data. "Fifty", -5, 1000
Path Coverage Ensures every logical branch (every IF/ELSE statement) is executed. Inputs that trigger both 'True' and 'False' cases.
Tip Test just inside, on and just outside each boundary: 0, 1, 2 and 99, 100, 101. Off-by-one errors are among the most common bugs, and boundary values are what catch them.

Boundary values

Boundary values are at the edges of what is valid. For every limit, test the value on it, the one just inside and the one just outside. For a mark from 0 to 100 that is −1, 0, 1 and 99, 100, 101. Most off-by-one errors, such as < written instead of <=, are only caught here. The boundaries between grade bands (49 and 50, 64 and 65, 84 and 85) need the same treatment.

Path coverage

Path coverage means the test data makes every route through the algorithm run at least once. Count the paths in the decision structure, then choose one input for each. This function has five paths (invalid, and four grades), so it needs at least five tests.

Pseudocode
BEGIN Classify (mark)
    IF mark < 0 OR mark > 100 THEN
        RETURN "Invalid"
    ELSE
        IF mark >= 85 THEN
            RETURN "High"
        ELSE
            IF mark >= 65 THEN
                RETURN "Medium"
            ELSE
                IF mark >= 50 THEN
                    RETURN "Pass"
                ELSE
                    RETURN "Fail"
                ENDIF
            ENDIF
        ENDIF
    ENDIF
END Classify (mark)

Faulty and abnormal data

Abnormal data is the wrong type or is outside the range the program should accept, such as the text "fifty", -5 or 1000 for a mark. Faulty data is data that contains errors: a missing field, a corrupted value, or entries that contradict each other. A robust program rejects or reports both instead of crashing or accepting them.

Typical Errors and Their Causes

🎯 (SE-11-06, SE-11-07)

📌 Determine typical errors experienced when developing code, including syntax, logic and runtime, and explain their likely causes

Understanding common error types helps programmers identify and fix problems systematically:

Syntax Errors

Definition: Violations of the programming language's grammar rules. The interpreter/compiler cannot parse the code and refuses to run it.
Likely Causes: Missing colons, mismatched brackets, incorrect indentation (Python), typos in keywords.if x > 5 (missing colon at the end) or for i in range(10] (mismatched bracket types).

Logic Errors

Definition: The program runs without crashing, but produces wrong results because the algorithm is flawed.
Likely Causes: Wrong operator (using + instead of ×), off-by-one loop errors, incorrect conditional logic, unreachable code.A loop from 0 to 9 when you intended 1 to 10 (off-by-one error), or calculating tax as salary × 0.01 instead of salary × 0.10 (operator error).

Runtime Errors

Definition: The program starts running but crashes during execution due to impossible operations or resource exhaustion.
Likely Causes: Division by zero, accessing an array index that doesn't exist, null pointer dereference, stack overflow from infinite recursion, out of memory.score[index] where index is 10 but the array only has 5 elements, or result = 100 / denominator when denominator is 0.

A logic error worked through

The program below runs without complaint, yet the answer is wrong. A student wants the average of two marks.

python
mark1 = 70
mark2 = 80
average = mark1 + mark2 / 2
print(average)
Output
110.0

The expected answer is 75.0. Division is done before addition, so Python calculates 70 + (80 / 2). The cause is operator precedence; the fix is brackets: (mark1 + mark2) / 2. Other common causes of logic errors are off-by-one loops, the wrong comparison operator (< for <=), a variable not reset before a loop, and a condition that can never be true.

Spot the error

Classify each fault, then check
  1. while count < 10 with no colon.
  2. A loop that adds prices but starts total at 1.
  3. names[len(names)] to get the last name.
  4. age = input("Age: ") followed by age + 1.

Answers. (1) Syntax error: missing colon. (2) Logic error: the run is fine but every total is one too high. (3) Runtime error (IndexError): the last index is len(names) - 1. (4) Runtime error (TypeError): input returns a string; convert with int().

Match the type to when it shows up: a syntax error stops the program before it starts, a runtime error stops it partway, and a logic error never stops it.
